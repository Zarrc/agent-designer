# Agent Rubric

## 先跑官方的，别重复造

`/doctor prompt-audit`（需 v2.1.283+）**已经会查** `.claude/` 下 subagents / skills / commands 的：

- 「为更老的模型写的指令」
- **引用了不存在的文件或命令**
- **文件之间互相矛盾**

→ **先跑它，再去补它不做的。** 本 skill 只覆盖官方不做的下面这些维度。

## 校验维度

### A. 路由（description）

- [ ] 给 **3 句「用户真的会说的话」**，能否命中？命中不了 → 触发语写得太抽象
- [ ] 是否有**边界句**（它不做什么 / 归谁）？
- [ ] skill 的 `description` + `when_to_use` 合并后 **≤ 1536 字符**（超了在 listing 里被截断，路由依据直接丢失）

### B. 边界与权限一致性 ⭐ 最常翻车

- [ ] `description` **声称的边界**与 `tools` **是否一致**？
  - 反例：description 写「只读 vault，不写简历」，`tools` 里却有 `Write, Edit`
- [ ] 写区是否显式列出「可写 / 不可写」？
- [ ] 能机械化拦截的约束，是不是该转成 **hook** 或 **`permissions.deny`**，而不是只写在自然语言护栏里？（自然语言护栏 **harness 不强制**）

### C. 结构

- [ ] 职责是否**单一**？一个 agent 塞 4 大块职责 → 该拆
- [ ] 是否把**稳定层**（人设 / 准则）和**易变层**（机器 / 版本 / 技术栈）混在一起？
- [ ] **锚点是不是真的 Markdown 标题**？（写成 `> ### 标题` 会让 `[[file#锚点]]` 指不到）
- [ ] 引用的路径 / 锚点 / 工具名**真的存在吗**？逐条去看，不要凭印象

### D. 引用真实性

- [ ] 每个外部仓库 / URL 都核实过吗？有没有编造？
- [ ] 未核实的，是否明确标了「未核实」？

### E. 选边声明

- [ ] `description` 范式（扁平散文 vs 引号触发语）是**明确选了**，还是随手写的？
- [ ] `model` 是显式决策，还是照抄 `inherit`？

## 静默失败四项（官方文档确认 —— 不会报错的坑）

| 检查 | 后果 |
|------|------|
| frontmatter 字段名拼写 / 大小写（是 `maxTurns` 不是 `maxturns`） | **静默忽略，不报错** |
| `SKILL.md` 第一行是不是 `---` | 否则整个文件（含 `---`）被当成正文 |
| `SKILL.md` 里的 YAML 能否解析 | 解析失败 → skill 仍加载，但**所有字段为空** |
| `name` 是否含 `:` | v2.1.218 起**直接被拒绝**（`:` 预留给插件作用域 ID） |

## 能跑的校验，就跑

| 场景 | 命令 |
|------|------|
| 插件 | `claude plugin validate <dir>` |
| 官方提示词体检 | `/doctor prompt-audit` |
| 路径存在性 | 逐条 `ls` / `Read`，不要凭印象 |

## 输出格式

```
## 校验结果：<定义文件名>

### 🔴 阻断（必须改）
### 🟡 建议
### ✅ 通过
```

**不许写「看起来没问题」。** 每条通过项都要说清**你实际查了什么**。
